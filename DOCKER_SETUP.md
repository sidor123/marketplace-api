# Docker Setup для Marketplace API

## Архитектура

Проект теперь использует раздельные Docker-контейнеры для каждого компонента:

### 1. **PostgreSQL** (`postgres`)
- **Образ**: `postgres:15-alpine`
- **Порт**: `5433:5432` (внешний:внутренний)
- **Назначение**: База данных для хранения всех данных приложения
- **Healthcheck**: Проверка готовности базы данных перед запуском зависимых сервисов

### 2. **Flyway** (`flyway`)
- **Образ**: `flyway/flyway:10-alpine`
- **Назначение**: Автоматическое применение миграций базы данных
- **Зависимости**: Ожидает готовности PostgreSQL
- **Режим работы**: Запускается один раз, применяет миграции и завершается

### 3. **Marketplace API** (`api`)
- **Образ**: Собирается из локального `Dockerfile`
- **Порт**: `8000:8000`
- **Назначение**: Основное приложение Flask API
- **Зависимости**: Ожидает готовности PostgreSQL и успешного завершения миграций
- **Режим работы**: Постоянно работающий сервис с автоматическим перезапуском

## Сетевая архитектура

Все сервисы работают в изолированной Docker-сети `marketplace-network`:
- Контейнеры могут обращаться друг к другу по именам сервисов
- PostgreSQL доступен внутри сети как `postgres:5432`
- API доступен снаружи на `localhost:8000`
- PostgreSQL доступен снаружи на `localhost:5433`

## Быстрый старт

### Запуск всех сервисов

```bash
make docker-up
```

Эта команда:
1. Запустит PostgreSQL
2. Дождется готовности базы данных
3. Запустит Flyway для применения миграций
4. Запустит API после успешных миграций

### Просмотр логов

```bash
# Все сервисы
make docker-logs

# Только API
make docker-logs-api

# Только PostgreSQL
make docker-logs-postgres

# Только Flyway (миграции)
make docker-logs-flyway
```

### Остановка сервисов

```bash
make docker-down
```

### Перезапуск сервисов

```bash
# Все сервисы
make docker-restart

# Только API
make docker-restart-api
```

### Полная очистка

```bash
# Удаляет контейнеры, сети и volumes (включая данные БД)
make docker-clean
```

## Конфигурационные файлы

### `docker-compose.yml`
Основной файл оркестрации, определяет все сервисы и их взаимосвязи.

### `Dockerfile`
Описывает сборку образа для API:
- Базовый образ: Python 3.11-slim
- Устанавливает зависимости из `requirements.txt`
- Копирует код приложения
- Запускает Flask на порту 8000

### `flyway.docker.conf`
Конфигурация Flyway для работы внутри Docker:
- URL подключения: `jdbc:postgresql://postgres:5432/marketplace`
- Использует имя сервиса `postgres` вместо `localhost`

### `flyway.conf`
Конфигурация Flyway для локальной разработки:
- URL подключения: `jdbc:postgresql://localhost:5433/marketplace`
- Используется при запуске миграций вне Docker

### `.dockerignore`
Исключает ненужные файлы из Docker-образа для уменьшения размера.

## Volumes

### `postgres_data`
Персистентное хранилище данных PostgreSQL. Данные сохраняются между перезапусками контейнеров.

## Порядок запуска

1. **PostgreSQL** запускается первым
2. **Healthcheck** проверяет готовность базы данных
3. **Flyway** применяет миграции после готовности БД
4. **API** запускается после успешного завершения миграций

## Разработка

### Горячая перезагрузка

API-контейнер монтирует локальные директории:
- `./app` → `/app/app`
- `./openapi` → `/app/openapi`

Изменения в коде автоматически подхватываются Flask в режиме разработки.

### Пересборка образа

После изменения `Dockerfile` или `requirements.txt`:

```bash
make docker-build
make docker-up
```

### Локальная разработка без Docker

Если нужно запустить API локально, но использовать Docker для PostgreSQL:

```bash
# Запустить только PostgreSQL
docker-compose up -d postgres

# Применить миграции локально
make migrate

# Запустить API локально
make run
```

## Troubleshooting

### Проблема: API не может подключиться к БД

**Решение**: Проверьте, что PostgreSQL запущен и готов:
```bash
docker-compose ps
make docker-logs-postgres
```

### Проблема: Миграции не применились

**Решение**: Проверьте логи Flyway:
```bash
make docker-logs-flyway
```

### Проблема: Порт 5433 или 8000 занят

**Решение**: Измените порты в `docker-compose.yml`:
```yaml
ports:
  - "5434:5432"  # для PostgreSQL
  - "8001:8000"  # для API
```

### Проблема: Нужно пересоздать БД

**Решение**:
```bash
make docker-clean  # Удалит все данные
make docker-up     # Создаст заново
```

## Преимущества новой архитектуры

1. **Изоляция компонентов**: Каждый сервис работает в своем контейнере
2. **Независимое масштабирование**: Можно масштабировать API отдельно от БД
3. **Простота отладки**: Логи каждого сервиса доступны отдельно
4. **Воспроизводимость**: Одинаковое окружение на всех машинах
5. **Автоматизация миграций**: Flyway применяет миграции автоматически при старте
6. **Управление зависимостями**: Docker Compose гарантирует правильный порядок запуска
